# P02d — authoritative debt dates, credit summaries and quick refund entry

DMP-037 native list now has debtor/all/credit/settled filters plus overdue/today/soon/future/undated debt filters. The server applies date/search/balance/store filters before pagination and reuses them for all matching-row exports. A real USD customer-credit summary was missing; both UZS and USD positive credit totals are now independent store-wide KPIs. Due filters require an outstanding positive balance in at least one currency; credit-only and settled customers do not qualify. Default active filtering and store/permission boundaries remain.

The business day comes from Django's configured Asia/Tashkent timezone, not the UTC date, active browser timezone or phone clock. Today is exact equality; soon means tomorrow through day7 inclusive; future means beyond7; overdue is strictly before today; undated means no due date. Invalid filter values return an inline field error for both list and export. The paged summary acknowledges version1, the exact applied filter, business date and7-day boundary. Native refuses an unacknowledged or incorrectly filtered page instead of displaying older-server unfiltered results under a false selected label. Existing balance/search access remains compatible when no due filter is requested.

Filters and summaries scroll with the list; five persistent quick tabs remain. Rows link directly to the customer statement, and actual owners can open the existing quoted refund sheet for either-currency credit. Pure credit/settled rows offer no ordinary debt-collection action. Selecting credit/settled clears a previous due filter. The search label now states actual supported fields (name, phone, note); it no longer claims unsupported STIR matching. Credit-only balances use normal text and the empty/more labels follow the selected balance filter.
