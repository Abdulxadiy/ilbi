# P01b — invitation and reset onboarding

New guarded native `/setup-account` and `/reset-password` routes inspect invitation/reset tokens, show purpose/store/position and masked account hints, validate username/password/confirmation inline, confirm a first password or resume pending2FA without changing it again, and hand the server login ticket to the existing Telegram/6-digit auto-submit login state machine. A ticket alone never authenticates a user. The login screen includes a direct entry for pasting the original ILBI email link.

Only exact `https://ilbi.uz/setup-account` or `/reset-password`, the configured `ilbi` scheme and a bounded opaque token are accepted by the pasted-link parser. The input never sets an API origin or redirect. The link input is masked; passwords and link state clear after handoff or an uncertain confirmation. Timeout/setup-already-started forces a read-only recheck before resuming. Stale session/token/server results cannot populate another setup screen. Tokens/tickets are never persisted by this feature.

**Verification:**564 mobile tests/64 suites, TypeScript and strict source/test ESLint pass;33 real password-reset/invitation backend tests pass (8 Django email-setting deprecation warnings) against the isolated test DB/cache with locmem email. Expo production export completes for Android, iOS and web. This is a JS/Hermes export, not signed native installation acceptance.

See browser-result.json and screenshots. The first browser attempt lacked a wait for the asynchronously loaded activation route; adding an explicit route/input wait resolved that harness failure. The final run has no unexpected adapter calls or browser errors.
