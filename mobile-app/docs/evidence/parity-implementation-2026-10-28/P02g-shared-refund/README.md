# P02g — shared web/desktop quoted refund confirmation and recovery

The shared Debts renderer now uses the strict server quote/commit protocol through scoped owner-only commands. The refund form displays the actual before/after two-currency balances and an explicit partial-refund confirmation. Changes invalidate the quote. A changed server calculation blocks a fresh journal/write and marks amount invalid. Numeric/reason and server-supplied currency/channel/branch errors are displayed on their specific controls. The old legacy correction fallback and optimistic local balance arithmetic are removed from this flow; acknowledgement is followed by an authoritative customer fetch and list refresh. Success says the refund was confirmed, rather than falsely claiming every balance was cleared.

Before a financial POST, IndexedDB stores the original customer, operation, amount/channel/branch/reason, quote and key under origin/account/store. Unknown results freeze the draft. Closing/reloading exposes an explicit pending-refund banner and resumes the original body/key without a new quote. A known accepted response followed by local-storage failure offers acknowledgement-only retry. Malformed receipts, corruption, unacknowledged storage, changed completed bodies and cross-scope state stay blocked/preserved. Session generation, token actor, actual selected store and owner memberships are checked before/after asynchronous work. Late quotes from a previous store cannot reopen its dialog or write. Source role and actual ownership control both list and detail entry, ignoring legacy staff owner-only grants. Older servers must be updated; no silent /correct/ fallback is used.

The real shared-page browser run discovered another part of DMP-039: the previous ternary hid refunds whenever a customer had any positive debt, even with credit in the other currency. The retained red run starts at UZS100/USD−10 and has no refund entry. Collection and owner refund now render independently in both list and detail, and zero/credit-only records no longer offer a fictitious positive collection action in detail. The owner browser test asserts both actions for this mixed balance.
