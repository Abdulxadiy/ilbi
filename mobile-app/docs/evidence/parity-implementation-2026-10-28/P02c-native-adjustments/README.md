# P02c — native quoted credit refunds and signed corrections

DMP-039 native source is connected to the exact P02b owner-only quote/commit protocol. The customer statement offers partial cash/card credit refunds and signed cash/card/bookkeeping corrections with a returning branch and mandatory reason. Owner role and both actual store memberships are checked in commands; staff cannot acquire the owner-only operation through a forged UI flag. The backend remains authoritative.

The amount/reason fields show inline errors. Calculation performs no financial write. Confirmation rechecks the server quote before a new durable intent. Any field change invalidates the previous calculation. Before posting, the record store saves the original body, nonce and idempotency key; uncertain results freeze the form. Retry and the sync journal replay that same persisted operation without recalculating its quote. Collection and adjustment share one pending family lock. A definitively rejected fresh request releases its lock; a previously uncertain request remains preserved even if a later replay is denied. A valid accepted receipt followed by failed local acknowledgement offers a storage-only retry. Malformed or cross-account/store/server receipts and corrupted journal metadata remain blocked. Neither opaque hashes nor original keys are displayed in the product UI.

Tests cover real fake-indexedDB transactions and journal dispatch, network loss, stale quote, original-key replay, old-server refusal without a legacy fallback, local-storage acknowledgement failure, changed completed drafts, forged authority and stale sessions. Component interaction checks cover signed input, field errors, invalidation, duplicate queued callbacks, frozen drafts, local-only retry and explicit journal navigation. These tests isolate network/native providers; they do not establish physical/native delivery or production acceptance.

The isolated production React Native Web/Chrome run uses an explicit controlled API adapter shaped from actual PostgreSQL/API fixtures. It verifies a USD10 credit, partial USD3 refund, lost accepted response, same-key replay with one effect, then a signed USD−2 correction: UZS100 stays unchanged and USD moves−10→−7→−5.
