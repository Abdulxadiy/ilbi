# P03b — frozen document identity and private/public separation

New sales capture cashier name, customer name/phone and B2B recipient-store name in a private versioned `receipt_snapshot.document_parties`. This happens inside the existing sale transaction; idempotent replay preserves its original snapshot. Private sale serializers use saved store/party fields when available, including intentionally empty values. Later profile, customer, store or linked-store edits cannot rename the original document. No historical snapshot is backfilled or rewritten, and no database model/migration is added.

Public receipt serialization now uses an explicit allowed-field list for the store/tax/layout snapshot and excludes every private party field, regardless of receipt-show-customer/cashier flags. Public store fields also use the saved store identity. The five retained red cases in `before-party-freeze.txt` reproduce the earlier renamed private fields/missing provenance. Real isolated API tests cover linked/unlinked buyers and both visibility settings, private detail, public anonymous access, idempotent replay and unchanged stored snapshots. Private names/phones never appear in the public DTO.

Private sale items expose nullable `receipt_product_snapshot_version`. Mobile receipt/A4 screen and HTML label legacy rows whose names/codes may come from today's catalog, and label old party identity as current/unknown. They never claim missing history is frozen. New saved party values override changed root fields, and known empty names cannot borrow a different current account/customer. The shared web/desktop invoice and thermal renderer use the same saved-identity policy; actual browser PDF assertions confirm original store/cashier/buyer names survive deliberately changed current fields. Legacy display remains available with an explicit printable notice. Signature cryptographic/content binding is still the next separate requirement; the existing shared local drawn-signature behavior is not certified here.

The cross-check also found that optional `BooleanField` parsing of QueryDict treated omitted `b2b_only` as false. General document/sales search therefore excluded every B2B sale without an explicit filter. `before-b2b-search-filter-fix.txt` retains the failing real API search. The endpoint now applies B2B exclusion only when the caller actually supplies the parameter; explicit true/false are independently tested. Search matches frozen buyer name/phone, cashier and recipient as well as current relations, and customer purchase search matches saved original product/variant names after catalog edits. An intermediate test used an unpaginated legacy response shape by mistake; it was corrected to send page1 like the mobile caller. No passing result is claimed for that failed intermediate run.

Sale and public receipt output also sort rows by saved line ID. A real fixture generation run exposed unspecified database row order; deterministic ordering preserves the selected source rows and prepares the document for later content-bound signatures without changing money or stock.
