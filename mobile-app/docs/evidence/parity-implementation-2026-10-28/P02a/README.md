# P02a — customer metadata, lifecycle and statements

Customer create now includes optional B2B target-store code, note and default debt date; edit sends only name/note/due date and preserves immutable phone/link. Exact date validation catches impossible dates inline. Archive requires confirmation plus a fresh zero balance in both currencies, and the server independently rejects outstanding debt/credit. Credit/settled and include-archive queries remain server-side.

The native customer statement route provides paginated all/debt purchases, saved net/refund amounts, server-wide summary counts, payment history with signed corrections/cash/card/none, branch, actor, note and exchange allocation. Balances come from the authoritative profile, not a partial loaded page. Each row/profile is checked against the requested customer; server-provided next URLs are never followed. Debt-only recorders can read statements without receipt/edit privileges. Native secondary routes preserve five quick tabs.

POS selection now retains B2B recipient and the customer's default debt deadline. Cart/picker show the receiving-store badge. A new customer's default date fills the payment draft; the same customer's manually edited deadline is preserved, and a different customer clears/replaces it. Metadata survives version3 draft restart with validation; no version bump/migration deletion was introduced. Quick customer creation also uses visible inline field errors and account/store scope guards.
