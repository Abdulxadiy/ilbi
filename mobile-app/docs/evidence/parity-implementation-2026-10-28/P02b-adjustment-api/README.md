# P02b adjustment API — DMP-134 and DMP-039 foundation

A real legacy owner-correction API regression reproduced a USD credit defect: starting at USD−10, a −3USD refund/correction left USD at−10, because collection's USD→UZS spillover allocation was used. New negative USD adjustments against existing USD credit now retain the selected currency. Legacy positive USD conversion and historical exchange-rate snapshots/replays keep their existing behavior; the full compatibility test remains unchanged.

The new owner-only POST `/sales/counterparties/{id}/payments/adjustment-quote/` and `/payments/adjust/` contract explicitly supports `credit_refund` (positive amount, cash/card, bounded by credit in that currency) and `correction` (signed amount, cash/card/none). Both explicitly retain one currency. Read-only quote binds actor, source/returning stores, customer, action, amount, currency, channel, reason and current balances with a server HMAC. The commit requires that exact quote and original idempotency key. No private signing secret enters the client.

Stores lock in a stable order before the customer; active ownership is rechecked. The locked customer serializes legacy/new callers. Balance, signed payment, key and fingerprint commit atomically; a key-save failure rolls back everything. Same-key retries return the same original receipt even after credit exhaustion, shift closure or customer archive; a new request on an archived customer is blocked. Changed payloads/keys cannot reuse stale quotes, and concurrent same-key/different-key API requests prove only one financial effect. Signed non-cash bookkeeping needs no open shift; a new cash request requires one. No model or database migration was introduced.

The strict native payload/quote/acknowledgement consumer strips opaque fields, checks integer cents, selected-currency arithmetic, credit bounds, actor/store/customer/branch, action/channel/reason, protocol, original key and quote token against `tests/contracts/debt-adjustments.json`, captured from the actual API. It is protocol preparation; the native/shared-renderer confirmation UI and durable journal hooks still need connection under DMP-039. No new refund button is claimed usable yet.

**Verification:**114 targeted PostgreSQL/API/permission/currency/schema checks pass; final unfiltered backend suite **1206 passes,0 errors/failures** (16 Django email-setting deprecation warnings). An intermediate run caught a positive-USD legacy compatibility regression and schema enum collisions. The fix preserves legacy conversion, adds an explicit internal same-currency mode for the new contract, and gives the enum a real schema name/reuses model payment choices. The tests/warning gate were retained, not suppressed. **606 mobile tests/66 suites**, TypeScript and strict source/test ESLint pass. Ruff passes on touched services/views/routes/tests; the existing settings file receives only the enum mapping. `makemigrations --check --dry-run` reports no changes.

Source is not deployed; no production ledger, APK, platform/app version or existing emulator changed. Previously stored financial transactions/rate snapshots are never silently rewritten. Potential historical negative-USD converted corrections require read-only identification and owner-reviewed reconciliation before any data change; this slice makes no claim that historical records were audited or repaired. Physical/native/cash/upgrade acceptance remains separate.
