# P02b authority — DMP-133

The backend correction endpoint incorrectly required only the assignable `sales.record_debt_payment` permission; its service also omitted the owner-only correction check. Separately, central permission checks still honored manually assigned legacy owner-only staff grants. A restricted cashier could use a bookkeeping correction to change a customer balance.

The correction API now requires `sales.correct_debt_payment`. The financial service independently checks that operation before locking/writing. Central checks deny all four non-assignable operations to staff and to non-owner memberships, even when an old database grant exists. The shared web/desktop refund entry and handler use actual selected-store ownership. Ordinary cashier collection remains assignable; actual owner correction remains available with a reason; platform administrators retain their existing retail-API exclusion. Financial receipt/idempotency/fiscal safeguards are preserved.
